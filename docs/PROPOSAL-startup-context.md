# PROPOSAL (draft, not approved): cut startup context cost

Author: Forge-22. Status: DRAFT. Nothing here is a rule until a ballot passes (M8).
Brainstormed with Phil 2026-10-21. Phil asked for the proposal only; no part is built.

## Problem
AGENTS.md tells every seat to read `docs/STATUS.md`, `SPEC.md`, `DECISIONS.md` first.
Measured 2026-10-21 (bytes/4, estimate):

| File | Bytes | ~Tokens |
|---|---|---|
| AGENTS.md | 12,026 | 3,000 |
| STATUS.md | 111,745 (363 lines) | 28,000 |
| SPEC.md | 12,564 | 3,100 |
| DECISIONS.md | 20,405 | 5,100 |
| HIVE-ROSTER.md | 4,605 | 1,150 |

A seat that obeys the rule spends ~36k tokens before its first action, on every session and every
restart. 78% of that is STATUS.md. It is meant to hold current state and the next step; it has
grown into a changelog ("Done" from line 250, Beta 2 lane history from line 155, per-seat reports).

## Proposal (three parts, independent, in priority order)

### P-A. Split STATUS.md into live + archive (largest win, no rule change)
- `docs/STATUS.md` keeps only: Active line, In progress, Open, Next step, Where things live,
  How to run, Machine facts, Problems. Target <= 8 KB (~2k tokens).
- Move "Done", Beta 2 lanes, R1 check, Beta 3.0 checklist, phone-access notes to
  `docs/STATUS-ARCHIVE.md`. Move verbatim, no rewriting, so nothing is lost. Keep a one-line
  pointer at the top of STATUS.md.
- Add `megazword status archive` (or a script) so a seat moves finished items out in one step; stops
  regrowth. Add a test asserting STATUS.md stays under a size cap (e.g. 12 KB) so the gate catches
  regrowth.
- Saves ~26k tokens per session start (~72% of startup).

### P-B. Memory index with lazy loading (needs ballot: changes AGENTS.md read order)
- New `docs/MEMORY-INDEX.md`, one line per memory file: path, size, "load when ...".
  e.g. `DECISIONS.md | 5k | load when changing/questioning a past choice`.
- AGENTS.md "Read first" becomes: read STATUS.md (now small) and the index; load others only when
  the task touches them.
- Index is generated by a script from file headers/front-matter, never hand-edited, so it cannot go
  stale; a test fails if the index is out of date.
- Saves a further ~8k (SPEC + DECISIONS) on tasks that do not need them.

### P-C. Skip flag (needs ballot)
- A task or prompt may carry `memory: skip` meaning "do not load the index or read-first files"
  (hello, one-off questions, pure code edits with explicit file lists).
- Default stays LOAD. Opt-out per task only, because a wrongly skipped load repeats old mistakes.
- Seats must not set the flag on work that claims shared items or edits STATUS/DECISIONS.

## Out of scope (separate proposals)
- Summarize-and-restart for long Megazword jobs (cost growth per step).
- Live text transcript viewer.
- Trimming AGENTS.md itself (3k tokens, re-sent every turn; high value, high sensitivity).

## Risks
- Archive move loses nothing but breaks links/greps that cite STATUS.md line numbers: grep docs and
  code for `STATUS.md` references first.
- Other seats edit STATUS.md concurrently; P-A must be one claimed task landed via the normal gate,
  announced in the room, with no other seat holding a STATUS edit.
- Size cap test could block unrelated pushes when STATUS.md grows; cap should have headroom.
- Lazy loading can make a seat miss a needed memory; index "load when" lines must be specific.
