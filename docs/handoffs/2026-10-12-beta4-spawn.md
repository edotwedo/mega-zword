## Design

The spawned bot is an ordinary CLI agent session (`claude -p`, `codex exec`, `grok` headless) that
Mega Zword starts and watches. Every one of these CLIs can run shell commands, so room access
is just two commands. No MCP is needed for v1:

- `megazword room say --by <bot-name> "..."` posts. This already exists.
- `megazword room show --since <msg-id>` returns new messages only. `--since` is new; today `show` only
  takes `-n`.

### Command

```
/spawn grok "review the Kitchen Stock app"
       --start-when "codex posts its branch"        # optional; default: now
       --leave-when "done" --max-usage 20 --max-minutes 90
```

The same command is available in the room (typed by Phil or by a bot) and as
`megazword room spawn ...` in the CLI.

### Pieces

- **S1 Worker table.** `~/.megazword/rooms/<room>.workers.json` (locked, atomic). Each entry stores the
  name (e.g. `grok-2`), backend, task, start rule, stop rules, status (waiting, running, done,
  stopped, out), pid, who spawned it, and usage at start.
- **S2 Start rules.** `now`, `after <time>`, or `when <bot> posts` / `when message matches <text>`.
  A small watcher checks the room log, so no AI is spent while waiting.
- **S3 Launch.** Run the backend's headless agent mode with a system note covering: your name, the
  task, the room commands, "check the room between steps", "post DONE: <summary> when finished",
  and the stop rules. Output goes to `~/.megazword/workers/<name>.log`.
- **S4 Stop rules, enforced by Mega Zword and not trusted to the bot:** DONE posted, max minutes,
  that AI's usage passing `--max-usage` points above its reading at start (live meters), Phil
  typing `/kill <name>`, or the room being stopped. On stop: kill the process tree, post
  "<name> bowed out: <reason>", and mark the status.
- **S5 Safety.** Spawned bots can spawn others only if Phil allows it (`allow_bot_spawn = false`
  by default). Cap of 3 workers at once. Write access only with `--edit`, using the same guards as
  `run --edit`. The secret/private-path guard (B15) applies to every message.
- **S6 Dashboard.** The Hive tab shows a worker strip with name, status, minutes and usage used,
  plus a Kill button.
- **S7 Tests.** Fake backends only, never a real CLI. Cover each start rule, each stop rule, the
  kill tree on Windows, the worker cap, and a crashed worker marked `out`.
