## Bugs

1. **H: `.mcp.json` is committed with Phil's local paths and runs the server from a worktree.**
   `.mcp.json:5-9` hard-codes `C:\Users\mrmar\mega-zword\.venv\Scripts\python.exe`
   and `PYTHONPATH=C:\Users\mrmar\mz-b2-grok\src`. So the Hive MCP server loads
   code from this B2 worktree, not from main. STATUS:12 says "Install only from
   `mega-zword`, never a worktree". The file also sets `MEGAZWORD_SEAT=claude`,
   so any CLI that reads this project file posts as `claude`. On any other
   machine or clone the server can't start.
   Fix: drop `PYTHONPATH`. Use `"command": "megazword", "args": ["mcp"]`, or
   gitignore the file and ship an `.mcp.example.json`. Set the seat name in each
   CLI's own config.

2. **H: any MCP caller can post as `phil`.** `mcp_hive.py:80` takes `author` from
   the tool arguments with no check, and `room.append_message` only lowercases
   it. GUIDE:134 says "Phil's messages always take priority". A seat can pass
   `author: "phil"` (or `floor`) and its message gets Phil's priority in the
   room. Fix: reject reserved names (`phil`, `floor`), or ignore `author`
   whenever `MEGAZWORD_SEAT` is set.

3. **H: `hive_wait` and `floor wait` can miss messages.** `floor.wait_for` takes
   its baseline from the message count *at call time* (`floor.py:162-163`).
   `mcp_hive.hive_wait` (`:86-90`) and `floor wait` (`floor.py:195`) never pass
   `after`. Any message that lands between a seat's `hive_read` and its
   `hive_wait` is lost to that seat. The seat then blocks until something newer
   arrives. That is a normal pattern in a busy Hive. Fix: add an `after` (count
   or timestamp) argument to the `hive_wait` schema and to `floor wait`, and
   return the new cursor in `hive_read`.

4. **H: `floor suggest bulk` points at seats that are known to be broken.** A seat
   counts as `seated` when its key env var is present (`free_apis.py:22-26`,
   `floor.py:52`). Only usage limits mark an AI out (`cli.py:648-658`). A 401 or
   403 never does. STATUS:3 says Groq returned 403 last night, but
   `floor suggest bulk` still prints `groq` first (`BULK_ORDER`, `floor.py:75`),
   and `hive_up.ps1:22` tells every seat to send bulk work there. Fix: mark the
   seat `broken` (or skip it in `suggest`) after recent auth failures in
   `log.jsonl`. Or, as a manual workaround tonight: `megazword out groq --until 1d`.

5. **M: `floor ready` says yes when no CLI can work.** `ready()` (`floor.py:65-72`)
   only fails on `empty`. If claude, codex and grok are all `out`, it prints
   `ready: yes`. FLOOR.md:11 says "seated or honestly marked out", which is
   intended, but at least one minimum-crew seat should actually be `seated`.
   Add `any(... == "seated")`. Add a test with all three out, since
   `test_ready_when_required_cli_seated_or_out` doesn't seem to cover that.

6. **M: `hive_wait` blocks the whole MCP server, with no cap.** `serve()` is
   single-threaded. A `hive_wait` with `timeout: 1e9` or `Infinity` hangs the
   server: `ping`, other tools and `notifications/cancelled` go unanswered.
   NaN or negative values return at once (`max(0.0, nan)` gives 0). Fix: clamp
   to something like 1-300 s and reject non-finite numbers.

7. **M: one bad item in a batch kills the MCP server.** For batches,
   `serve()` (`mcp_hive.py:193-197`) calls `handle()` outside the
   `try/except` that the single-message path uses (`:200-205`). A batch item
   with `"params": [..]` (positional params are valid JSON-RPC) raises
   `AttributeError` at `params.get`. That ends `serve()`, and the seat loses
   the Hive. Fix: wrap each batch item like the single path. Also check that
   `params` is a dict and return -32602 otherwise.

8. **M: negative `Content-Length` reads stdin to EOF.** `mcp_hive.py:158-163`:
   `int("-5")` succeeds, and `stream.read(-5)` blocks until stdin closes.
   There's no upper bound either. Fix: reject `length < 0` and lengths over a
   limit (for example 1 MB, the same as the dashboard).

9. **M: `megazword mcp` lacks the stdout guard that `python -m megazword.mcp_hive` has.**
   `mcp_hive.py:211-214` points `sys.stdout` at stderr so a stray print can't
   corrupt the JSON-RPC stream. `cli.py:309-311` calls `serve()` directly.
   `config.load_user_env()` (`cli.py:301`) and any import-time print run with
   the real stdout. Fix: in the `mcp` branch, keep `sys.stdout.buffer`, swap
   `sys.stdout = sys.stderr`, and pass the buffer to `serve()`.

10. **M: `--timeout 0` and `-n 0` are silently replaced.** `floor.py:191` and
    `:194` use `... or 10` and `... or 120`. So `floor wait --timeout 0` (a
    non-blocking check) blocks for 120 s, and `peek -n 0` prints 10. Use
    `is None` checks. Also, `cli.py:122` makes `--timeout` an int while
    `hive_wait` takes a float.

11. **M: `floor --room` with a bad name prints a traceback.** `room._valid_room`
    raises `ValueError` (`room.py:58-61`). `floor.command` doesn't catch it, and
    neither does `main()` for the floor branch (`cli.py:388-390`). C8 promised
    one-line errors. `save_snapshot` has also already run by then.

12. **L: `hive_read` with `n <= 0` prints "(no messages yet)" even when messages exist.**
    `mcp_hive.py:71-72`. Clamp to 1 like `floor.peek_text`, or return an error.

13. **L: MCP `initialize` echoes back whatever protocol version the client sent.**
    `mcp_hive.py:112`. The server should answer with a version it supports
    (`PROTOCOL_VERSION`) when the client's version is unknown.
    `SERVER_INFO.version` is hard-coded `"0.1.0"`; use `megazword.__version__`.

14. **L: every `floor` action rewrites `floor.json`**, including `peek`, `wait`
    and `suggest` (`floor.py:178-179`). The write isn't atomic, unlike the
    other state files (`write_atomic`), and it uses `__import__("json")`
    (`:124`). Move `save_snapshot` to `status` and `introduce`, and use
    `filelock.write_atomic`.

15. **L: an `@mention` sent through MCP spends a one-shot.** The `hive_say`
    description says "No @mentions required" (`mcp_hive.py:33`), but a mention
    still wakes that bot when `room start` is running (`room.py:295-298`).
    `floor introduce` avoids mentions on purpose (`floor.py:128-129`). Say this
    in the tool description so seats don't wake a paid one-shot by accident.
